1. GPU 使用率 (%)

システム全体（info 画面の GPU %）

参照元: IOReport（Apple 私有 framework、-lIOReport 経由でリンク）→ channel group "GPU Stats" → subgroup "GPU Performance States" → channel "GPUPH"

導出方法: residency ベース。各 performance state の滞留時間（IOReportStateGetResidency）をサンプリング窓で集計し、以下を計算:

active% = (totalTime − OFF/IDLE/DOWN 状態の時間) / totalTime × 100

つまり「GPU がアクティブなクロック状態だった時間の割合」。ワークロード量やコマンドキュー深さではない。

  • 電力: "Energy Model" group の "GPU Energy" チャネル（W）
  • 周波数: 各 state 周波数の residency 加重平均（g_gpu_freqs は IOKit voltage-states9 から取得、GetMaxGPUFrequency）

実装: internal/app/ioreport.m:2751-2790（gpuActive 算出）、3142（gpuPower 確定）

プロセス別 GPU %

参照元: IOKit AGXAccelerator → 子サービス AGXDeviceUserClient

  • 各エントリの accumulatedGPUTime プロパティ（ns 単位の累積 GPU 時間）を読み取り
  • PID は IOUserClientCreator（"pid NNN, WindowServer" 形式）を sscanf で解析

導出: tick 差で ms/s を算出し、全プロセス合計がシステム GPU% と整合するよう scale 補正（scaleFactor = systemGpuPercent / rawTotalPercent）。表示値は ms/s ÷ 10（1000 ms/s = 100%）。

標準ツールでは取得できない: AGX（Apple GPU ドライバ）内部カウンタ由来のため、ps / top / sysctl では参照不可。

実装: internal/app/processes.go:259-297（updateProcessGPUMetrics）、internal/app/native_stats.go:362-403, 1295-1313

2. DRAM 帯域 R/W GB/s

samplePowerMetrics 内の優先度チェーン（上から順に判定）:

#ソース内容
1 AMC Stats（第一候補） DCS（DRAM コントローラ）通過の正確な R/W バイトカウンタ。複数世代の channel 命名に対応（Exact / Partition / Client、Directional / Combined）
2 PMP DRAM BW AMC が無い/ストール時の rate histogram フォールバック。3 回連続ゼロ + トラフィック推定（fallbackTrafficLikely）で有効化され、1 サンプル非ゼロで再無効化
3 電力ベース推定 BW = max(0, dramPower − idlePower) × g_dramGBsPerWatt。係数はハードコードでなく、calibThread がバイト数と DRAM 電力 delta を同時計測して実行時キャリブレーション（initKperfDramBW + calibrateDramBwFromPower）。R/W は均等分割（電力では方向を判別できないため）
4 kperf PMU root 必須の最終手段（readKperfDramBW）
5 AMC request bytes fabric パスで過計上リスクのため最下位（物理 DCS ソースが全欠如時の互換フォールバック）

GB/s 化は「bytes ÷ 実測窓」。窓は 2 回の IOReportCreateSamples の前後に取得した mach_absolute_time（actualDurationNs）を使用し、スケジューラジッター下でも Go 側の除算と完全往復一致する。

実装: internal/app/ioreport.m:3148-3288（優先度チェーン）、700-1150（キャリブレーション機構）

3. プロセス別メモリ

processOsProc（internal/app/processes.go:84-161）:

項目参照元導出
RES (RSS) proc_pidinfo(pid, PROC_PIDTASKINFO) → pti_resident_size ps -o rss や top の RES 列と同一値。footprint (MYS+PWT) ではない
VIRT (VSZ) pti_virtual_size ps の VSZ と同一
MEM% RSS ÷ sysctl(CTL_HW, HW_PHYSMEM)（= hw.memsize）× 100 物理 RAM 総量に対する割合（使用量に対する % ではない）
CPU% pti_total_user + pti_total_system の delta（tick→ns は mach_timebase_info で換算）÷ wall-clock delta top / ps と同一アルゴリズム
プロセス列挙 sysctl KERN_PROC_ALL → kinfo_proc[] macOS には /proc が無いため sysctl を使用。CPU 順ソート後上位 500 プロセスに截断

4. システムメモリ

GetNativeMemoryMetrics（internal/app/native_stats.go:868-912）:

host_statistics64(HOST_VM_INFO64) → vm_statistics64
available = free_count + inactive_count   （× pageSize）
used      = total − available             （total は hw.memsize）
swap     = sysctl("vm.swapusage")

vm_stat と同じ計算式。

5. top / 標準ツールとの差の要点

  • RES / VSZ / CPU% は ps・top と同一 API 系（sysctl KERN_PROC、proc_pidinfo）のため数値は一致する。macOS に /proc は無く、mactop も同様のカーネルインターフェースを使用
  • mactop の RES = pti_resident_size = top の RES 列（footprint / MYS+PWT ではない）
  • 異なる点（すべて Apple 内部 API 由来で標準ツール非公開）:
    • プロセス別 GPU — AGX ドライバカウンタ
    • GPU active% — IOReport residency
    • DRAM R/W バイト — AMC / PMP 内部カウンタ（電力推定は実行時キャリブレーション）
    • ANE メトリクス — PMP ANE-AF-BW / ANE-DCS-BW floor residency + rate histogram
