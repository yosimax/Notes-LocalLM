概要

mactop は macOS のシステム監視ツール。Go + C(cgo) を組み合わせて、 IOKit / Mach / IOReport / SMC などの OS 固有の API から各種メトリクスを取得している。

調査対象:

  • GPU 使用率と GPU DRAM 帯域の表示値と導出元
  • 各プロセスメモリサイズ (予約/使用) と、標準 top や /sys/proc 値との違い
重要: /sys/proc/ は Linux 固有のパスで、macOS には存在しない。 macOS 側でプロセス情報を取得できるのは kinfo_proc (sysctl) と proc_pidinfo(PROC_PIDTASKINFO) のみである。mactop はこれらを基にしている。

1. 各プロセスメモリ (VSZ / RSS)

導出先: internal/app/processes.go:110

func processOsProc(...) (ProcessMetrics, int, ProcessTimeState, bool) {
    // ...
    var taskInfo C.struct_proc_taskinfo
    ret := C.proc_pidinfo(C.int(pid), C.PROC_PIDTASKINFO, 0,
                        unsafe.Pointer(&taskInfo),
                        C.int(C.sizeof_struct_proc_taskinfo))
    if ret == C.int(C.sizeof_struct_proc_taskinfo) {
        rssBytes = int64(taskInfo.pti_resident_size)   // RSS
        vszBytes = int64(taskInfo.pti_virtual_size)     // VSZ
        rawTime  = uint64(taskInfo.pti_total_user) +
                   uint64(taskInfo.pti_total_system)
        // ...
    }
    // ...
    pm := ProcessMetrics{
        VSZ: vszBytes / 1024,
        RSS: rssBytes / 1024,
        Memory: memPercent,   // RSS / totalMem * 100
        // ...
    }
}
値ソースフィールド意味
RSS pti_resident_size 実在メモリ（物理 RAM を実際に占有している部分）。ページ単位で換算。
VSZ pti_virtual_size 仮想アドレス空間の総サイズ（共有メモリを含む）。
Memory 列 RSS / totalMem 全メモリに対する該当前プロセスの割合。 totalMem は sysctl (KERN_VM_MEMORYSIZE、mib[6].mib[24]) で取得。

2. 各プロセス CPU%

導出先: internal/app/processes.go:114,119

Mach タスク情報 API の pti_total_user + pti_total_system（timebase でスケール）を、 前サンプルまでの時間差分で割って % を計算する。

totalTimeNs = (pti_total_user + pti_total_system) * numer / denom cpuPercent = (totalTimeNs - prevTime) / wallDelta * 100 // wallDelta = now - prevTimestamp (実測の時間間隔)

これは top の全体ロードアベレージからプロセス別に割り当てる方式とは計算元が異なり、 各プロセスの「CPU に費やした時間」を直接取得できる。

3. 各プロセス GPU

導出先: internal/app/processes.go:258-297（updateProcessGPUMetrics）

データソース

AGXDeviceUserClient（IORegistry）の AppUsage[] 配列から accumulatedGPUTime（ナノ秒、累積値）を取得する。

// Sum all accumulatedGPUTime from AppUsage array
for each entry in AppUsage:
    gpuTimeNs = entry["accumulatedGPUTime"]  // 累積 GPU 時間（ns）

計算式

gpuMsPerSec[pid] = (currentTime - prevTime) / gpuElapsed / 1_000_000 // ms/s totalRawGpuMs = Σ gpuMsPerSec rawTotalPercent = totalRawGpuMs / 10.0 scaleFactor = systemGpuPercent / rawTotalPercent process.GPU = gpuMs * scaleFactor // scaleFactor: 各プロセスの GPU 時間をシステム全体の GPU 使用率に // 比例して正規化（GPU 使用率を 0-100% に合わせる）

つまり、各プロセスの GPU 使用率は「GPU 時間を ms/s で求め、システム全体の GPU 使用率に 比例補正」した値になります。

4. システム GPU Active%

導出先: internal/app/ioreport.m:2784

IOReport の 「GPU Stats」→「GPU Performance States」 グループから、 パフォーマンス状態のレジデンス（各状態での滞在時間）を解析し、アクティブな状態の割合を計算する。

for each performance state:
    residency = IOReportStateGetResidency(item, s)
    name       = IOReportStateGetNameForIndex(item, s)

    totalTime += residency
    if name not in {OFF, IDLE, DOWN}:
        activeTime += residency
// ...
metrics.gpuActive = activeTime / totalTime * 100.0   // アクティブ率 %
metrics.gpuFreqMHz = weightedFreq / activeTime        // 平均クロック (MHz)

Go 側では ioreport.go:269 で GPUActive を SocMetrics に格納し、 metrics.go:220-227 の gpuMetricsFromSoc で GPUMetrics.ActivePercent へ変換。 info.go:92 で Info_GPUUsage として画面に表示されます。

5. GPU DRAM 帯域 (GB/s)

導出先: internal/app/ioreport.m:3148-3288

IOReport Energy Model のバイトカウンタを、実測の時間間隔 (actualDurationNs) で割って GB/s に変換します。 ioreport.go:195-213 でこの除算を実行。

intervalSec = actualDurationNs / 1e9 // 実測時間間隔（秒） dramReadBW = dramReadBytes / intervalSec / 1e9 // GB/s dramWriteBW = dramWriteBytes / intervalSec / 1e9 dramBWCombined= (read+write) / intervalSec / 1e9

バイトソースの優先順位（チップ/OS により変動）

順位ソース対応チップ備考
1 AMC DCS (amcExactDcs*) M1-M4 正確なバイト数。優先される主要ソース。
2 PMP DRAM (pmpDram*) M5+ AMC からフォールバック。方向別 / 合計から読み取り推定。
3 電力推定 任意 DRAM 電力から推定。アイドル電力を差し引いた動的電力 × 校正定数。
4 kperf PMU 任意 root 権限を必要。DRAM 帯域を直接計数。
5 request bytes (amcRequest*) 任意 最終手段。fabric 経路を含むため過大計上の可能性。

各ソースの取得詳細は ioreport.m:3148-3288 に分岐が記載されています。 AMC が 0 を返した場合、トラフィックが検出可能ならフォールバックを切り替え、 必要に応じて PMP チャンネルの確保やバックグラウンド校正が実行されます。

6. システムメモリ

導出先: internal/app/processes.go:220-226

mibMem = {6, 24}   // sysctl KERN_VM_MEMORYSIZE
sysctl(&mibMem[0], 2, &memSize, &memLen, ...)
totalMem = uint64(memSize)   // システム全体の物理メモリ (bytes)

これは各プロセスの Memory 割合を計算するための分母です。

7. top コマンドとの差異

値mactop標準 top差異
RSS proc_pidinfo(PROC_PIDTASKINFO).pti_resident_size kinfo_proc.ki_rssize（ページ単位） 値は同一（実在メモリ）。取得 API が異なる。
VSZ pti_virtual_size kinfo_proc.ki_vsize 値は同一（仮想サイズ）。取得 API が異なる。
Memory 列 RSS / KERN_VM_MEMORYSIZE 同様に RSS / 総メモリ 計算元はほぼ同一。
CPU% プロセス別 Mach タスク情報
pti_total_user/system の差分		 全体ロードアベレージからプロセス別に割り当て 計算元が異なる。 mactop は各プロセスの CPU 費用工時間を直接取得。
GPU GPU 時間
accumulatedGPUTime の差分		 GPU クロック / エネルギーモデル 計算元が異なる。 mactop は GPU 費用工時間、top はクロック/電力。
補足: /sys/proc/<pid> は Linux 固有で macOS には存在しない。 macOS ではプロセス情報を取得できるのは上記の kinfo_proc / proc_pidinfo のみ。 mactop はこれらを基に、top と同じ RSS/VSZ を取得しつつ、CPU/GPU は独自の導出方式を採用している。
