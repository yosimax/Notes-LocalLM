mactop 調査結果

macOS システム監視 CLI/TUI の表示値のソースと計算式を特定した調査メモ

概要

mactop は macOS のシステム監視ツール。cgo を用いて IOKit / CoreFoundation / mach / libproc / SMC / IOReport を直接呼び出し、GPU・DRAM・CPU・メモリ・温度・ファン・バッテリー・ネットワークなどを取得している。 本調査では、表示される「GPU 利用率」「GPU DRAM バンド幅」「プロセス別メモリサイズ」の正確なソースと計算式を特定した。

重要なファイル

ファイル役割
internal/app/ioreport.m IOReport / CoreWLAN / SMC / HID のサンプリング。GPU / DRAM / 電力 / ANE のロジック。主要なソース
internal/app/ioreport.go Go ラッパー。SocMetrics 構造体定義、sampleSocMetrics（C 構造体→Go 変換・GB/s 計算）
internal/app/processes.go プロセス別メモリ / CPU / GPU（kinfo_proc + proc_pidinfo）
internal/app/native_stats.go プロセス別 GPU 統計、ネットワーク、misc 原生ヘルパー
internal/app/metrics.go Prometheus レジストリ + 指標名
internal/app/processes_helpers.go テーマ/色ヘルパー

1. GPU 利用率 (gpuActive, %)

一次ソース

出どころ

IOReport の "GPU Stats" / "GPU Performance States" サブグループ、チャネル GPUPH（状態チャネル）。

計算式

gpuActive = activeTime / totalTime × 100

active = OFF / IDLE / DOWN を除く状態の合計（ioreport.m:2756-2789）。

プロセス別 GPU% の表示

表示値 = gpuMsPerSec / 10 （buildProcessRows:501。1000 ms/s = 100%）

2. GPU DRAM バンド幅 (dramReadBytes / dramWriteBytes)

一次ソース バックアップチェーン

一次: AMC Stats の DCS チャネル

正確な集計 DCS → パーティション DCS → クライアント DCS

RD/WR の分割は amcChannelDirection（ioreport.m:2934-2974）:

  • RD+WR / RW = 両方（combined）
  • RD = read
  • WR = write

バックアップ（AMC Stats が無い場合）

順位ソース行
1PMP "DRAM BW"ioreport.m:3214-3223
2電力から算出する推定（較正済み DRAM 電力）ioreport.m:3252-3269
3kperf PMU（root 権限）ioreport.m:3271-3278
4AMC リクエストカウンタioreport.m:3283-3288

バイト → GB/s の変換

Go が bytes / intervalSec / 1e9 で GB/s に変換する。 intervalSec は actualDurationNs（2つの IOReport スナップショットを取り囲んで mach_absolute_time で取得した実wall-clock 間隔）。これは schedulering ジッターに依存しない正確な値。 （ioreport.go:195-213）

3. プロセス別メモリ

プロセス別メモリ

出どころ

processes.go:109-116 の proc_pidinfo(PROC_PIDTASKINFO) から取得:

項目フィールド単位
RSSpti_resident_sizeKiB
VSZpti_virtual_sizeKiB

計算式

  • RSS bytes = rssBytes / 1024
  • VSZ bytes = vszBytes / 1024
  • Mem% = rssBytes / totalMem × 100（totalMem は sysctl {6,24} から）
  • CPU% = (user + system ticks を mach timebase で取得) / wallDelta × 100

注: top や /proc とはソースが異なり、libproc + mach VM を通じて直接取得している。

4. プロセス別 GPU

ソース

native_stats.go:1296 の GetGPUProcessStats() が get_gpu_process_stats() を呼び出し、 pid → gpu_time_ns を返す。

計算式

  • 2つのサンプル間のdelta（経過秒数）で ms/s に変換
  • スケール係数 = systemGpuPercent / rawTotalPercent（生合計%）で補正
  • プロセス別%の合計がシステム GPU% に一致するように補正

（updateProcessGPUMetrics:258-297）

表示

表示 GPU% = gpuMsPerSec / 10（buildProcessRows:501）。

5. 電力 / 温度 / 熱状態

電力

IOReport Energy Model チャネル（GPU Energy, CPU Energy, DRAM, ANE）+ SMC "PSTR" で systemPower（ioreport.m:2699-2750, 3299-3301）。

温度

期待コア数と検証した HID パーコアセンサー、無いと SMC（ioreport.m:3299-3448）。

熱状態

カーネル notify "com.apple.system.thermalpressurelevel"（getThermalState:3519）。

6. 採集フロー（GPU/DRAM/電力）

  1. 2つの IOReport スナップショットを取得（usleep(durationMs) 間隔）。
  2. mach_absolute_time で実間隔 actualDurationNs を取得（IOReportCreateSamples 返り後、post-snapshot 過頭を相殺）。
  3. IOReportCreateSamplesDelta でデルタを計算し、チャネル配列を取得。
  4. チャネルグループごとに解析（Energy Model / GPU Stats / CPU Stats / AMC Stats / PMP）。
  5. 電力は per-block vs aggregate を考慮し二重カウントを避ける。バイトは DCS 系列の最優先ソース。
  6. Go が actualDurationNs で割って GB/s を算出。
