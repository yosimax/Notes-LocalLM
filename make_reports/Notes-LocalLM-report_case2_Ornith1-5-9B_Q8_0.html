1.1 生成速度 tg の安定性 Generation speed (tg) stability

Qwen3.8-27B-UD-Q2_K_XL の最大の特徴は、生成速度が極めて安定していることである。 1.log では 4.99 → 3.82 t/s、2.log では 4.82 → 4.97 t/s と、 全セッションを通じて 約 4-5 t/s の帯域で推移する。 9B モデルの 10-15 t/s に比べ約 3 分の 1 の速度であり、27B の重量を反映している。

1.2 コンテキストサイズ・時間経過 vs 処理速度の逆相関 Inverse correlation: context/time vs speed

① 生成速度は時間経過（コンテキスト蓄積）に伴い緩やかに低下する

1.log:  4.74 → 4.56 → 4.18 t/s   （-12% の低下）
2.log:  4.69 → 2.30 → 3.27 t/s   （中段で一時低下、その後回復）

  コンテキストが蓄積するにつれ、per-token 速度は反比例して低下する。
  ただし 2.log は回復傾向を示し、24GB 環境では持続可能である。

Generation speed drifts down as context accumulates over time (1.log: -12%). 2.log dips mid-session then recovers — sustainable on 24GB.

② プロンプト処理速度はより変動が大きく、ボトルネックとなる

1.log:  63.68 → 39.95 → 40.80 t/s   （-37% の低下）
2.log:  50.34 → 40.11 → 39.62 t/s

  生成速度は安定但对話速度はプロンプト評価で制約される。
  2-135 t/s の広範囲で変動し、実際の応答遅延の主要因である。

Prompt processing is the bottleneck (2-135 t/s), declining ~37%. It is far more variable than generation and dominates perceived latency.

考察（Takeaway）

中央値（約 180s）が「待ち時間を除いた実処理間隔」を表す。 平均は長時間の待機（ユーザープロンプト間のアイドル時間）で 4-4.6 倍に膨らむ。 実際の処理負荷は中央値で評価すべきであり、平均値は待機ノイズを含む。 生成/プロンプト処理のイベント比は約 14-16:1 で、生成が主体である。

1.5 Qwen3.8-27B-UD-Q2_K_XL の傾向と考察 Trends & Reflections: Qwen3.8-27B-UD-Q2_K_XL

  • 安定生成 Stable generation: 約 4-5 t/s を全セッション維持。長時間タスクでも破綻しない。

4.1 相関分析 Correlation Analysis

① モデルサイズ ↑ → 処理速度 ↓（明確な逆比例）

Ornith-9B-Q4  ≈ 15 t/s
Ornith-9B-Q8  ≈ 10 t/s
Qwen-27B-Q2   ≈  4.5 t/s   （平均）

  27B は 9B の約 3.3 倍遅い。
  9B-Q8 は 9B-Q4 の約 0.67 倍の速度。

Clear inverse proportionality: speed drops as parameter count rises. 27B ≈ 3.3× slower than 9B-Q4; 9B-Q8 ≈ 0.67× the speed of 9B-Q4.

② 同一サイズで 量子化 ↑ → 速度 ↓ だが 容量 ↑（トレードオフ）

9B-Q4:  15 t/s  →  4304 tokens
9B-Q8:  10 t/s  →  7667 tokens   （約 1.78 倍のトークン容量）

  速度比  Q4:Q8 = 15:10 = 1.5 : 1.0
  容量比  Q4:Q8 = 4304:7667 = 1.0 : 1.78

At fixed size, higher quantization precision costs speed but buys capacity: Q8 runs 33% slower yet generates 1.78× more tokens — speed vs capacity trade-off.

③ コンテキスト/内容サイズ ↑ → per-token 速度 ↓（ウォームアップ傾向）

Q4_K_M:  11.0 t/s （初期） → 15.4 t/s （ピーク）  上昇
Qwen 27B: 3.8 t/s  （初期） → 6.6 t/s  （ピーク）  上昇
Q8_0:    10.0 t/s  （ほぼ平坦）

  初期はプロンプト評価が重い → 以降、プロンプトキャッシュで生成速度が安定/上昇。

Throughput rises as the prompt cache warms; Q8_0 stays flat (~10 t/s) because it sustains longer total tokens, keeping KV pressure steady.

結論（Takeaway）

モデルサイズと速度は明確に反比例するが、24GB 環境では 9B が 27B より圧倒的に速く、 長時間生成に有利。Q4 vs Q8 は「速度 vs 精度/容量」のトレードオフで、 大容量・長時間出力には Q8_0、速度優先なら Q4_K_Mが選べる。 コンテキスト成長に伴う速度低下はプロンプトキャッシュで相殺され、 安定して動作することが確認できた。

6. 考察: M4 24GB で安定動作するモデル/オプション 6. Reflections: Stable configs on M4 24GB

case1 で特定した、メモリスワップしない安定動作の条件を base として、各モデルの妥当性を評価する。

条件内容

  • Ornith-1.5-9B-Q4_K_M Fastest (15 t/s peak). Best for long coding loops where latency matters. 128K context fits 24GB.
  • Ornith-1.5-9B-Q8_0 Highest token capacity (7667) at flat 10 t/s. Better precision; slightly heavier on memory.

留意点（Caveat）

27B は速度が 9B の約 1/3 であり、長時間生成には不向き。 分析・調査タスク（mactop 調査など）では出力量が小さいため、速度より品質が優先される。

8. 結論 8. Conclusion

  • 速度優先 Speed-first: Ornith-1.5-9B-Q4_K_M（128K ctx, 約 15 t/s）。
  • 大容量/高精度 High capacity/precision: Ornith-1.5-9B-Q8_0（約 7667 tokens, 平坦 10 t/s）。
  • 品質優先 Quality-first: Qwen3.8-27B-UD-Q2_K_XL（分析タスク、約 4.5 t/s）。
  • 安定動作 Stability: case1 で得た KV-cache Q8_0 @ 80K + compaction.auto=true + per-model limits を踏襲。

On 24GB M4, 9B models dominate for long coding; 27B excels at analysis. Prompt caching keeps per-token speed stable as context grows.
